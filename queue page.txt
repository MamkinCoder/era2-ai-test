Queue Page Spec

Goal

Implement a full-screen queue page for generation tasks.

The page shows all mocked generation tasks and lets the user inspect, filter, sort, cancel, retry, and clear completed tasks.

Route:

/queue

⸻

Architecture

Follow the current project structure.

Queue logic and queue UI are separate.

Queue state lives in:

entities/generation/model/

Queue page UI lives in:

components/workspace/queue-page/

Route file lives in:

pages/QueuePage.tsx

⸻

pages/QueuePage.tsx

Route-level page only.

Responsibilities:

* set document title if needed
* render QueuePageContent
* no queue logic
* no filtering logic
* no sorting logic

⸻

QueuePageContent.tsx

Main page container.

Responsibilities:

* read queue state via useQueue()
* own local filter state
* own local sort state
* derive visible tasks
* derive stat counts
* compose header, stats, toolbar, task list

Uses:

* QueuePageHeader
* QueueStatsGrid
* QueueToolbar
* QueueTaskList

* own queue engine logic
* own timers
* mutate task state directly

Data Source

entities/generation/model/queue-context.tsx

Using:

useQueue()

Expected queue API:

const {
  tasks,
  cancelTask,
  retryTask,
  clearCompleted,
} = useQueue();

Exact names can change, but responsibilities stay the same.

⸻

Filtering

Filtering is local UI state inside QueuePageContent.

Rules:

all      -> show all tasks
queued   -> status queued
running  -> status running
done     -> status done
failed   -> status failed

If cancelled is implemented:

* cancelled can appear under all
* optionally add cancelled tab later
* not required by current design

⸻

Sorting

Sorting is local UI state inside QueuePageContent.

Rules:

newest      -> createdAt descending
oldest      -> createdAt ascending
activeFirst -> running, queued, failed, done, cancelled

⸻

Stats

Stats are derived from full task list, not filtered task list.

Counts:

* queued
* running
* done
* failed

Cancelled is not displayed in top stat cards unless added later.

Responsive Behavior

Desktop

* stats in 4 columns
* task cards are horizontal rows
* actions on right
* progress visible inline

Tablet

* stats in 2 columns
* task cards remain mostly horizontal if width allows
* actions can wrap if needed

Mobile

* stats in 2 columns or 1 column
* toolbar wraps
* task card becomes vertical
* actions move below metadata/right section
* progress takes full width

Animation

Use Framer Motion where useful.

Required:

* animate task progress bar width
* animate task entering/removing from list
* animate filter/sort list transitions if simple

Do not overbuild.

Task row animation:

exit: opacity 0, y -8

Use AnimatePresence around task list if convenient.

⸻

Actions

Cancel

Available for:

* queued
* running

Behavior:

* call queue engine cancel action
* task becomes cancelled or removed depending queue engine decision

Retry

Available for:

* failed
* cancelled if supported

Behavior:

* call queue engine retry action
* task re-enters queue

Clear completed

Available when at least one done task exists.

Behavior:

* remove done tasks from queue state
* should not remove running/queued/failed

Download

Available for:

* done

Behavior:

* mocked action allowed
* no real file needed

More

Optional.
Can be visual only for this assignment unless specific menu behavior is needed.

⸻

Non-Responsibilities

Queue page does not implement:

setInterval
progress ticks
FIFO
MAX_CONCURRENT
random failure
timer cleanup

Those belong to:

entities/generation/model/queue-engine.ts

Queue page does not call real backend.

Queue page does not own source of truth.

Queue page is view/controller only.
